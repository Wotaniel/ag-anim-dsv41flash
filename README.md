# AdGuard v5 is here — анимация In-App Event (AG-60517)

Два проекта для **ручной анимации в Keyshape**: карточка 16:9 и деталка 9:16.
Луп 10 секунд, 60 fps, чёрный фон, персонаж Agnar King, зелёное свечение, статичный UI.

| Файл | Что это |
| --- | --- |
| `AG-60517 Event Card 16x9.keyshape` | проект Keyshape, 1920×1080 |
| `AG-60517 Event Details 9x16.keyshape` | проект Keyshape, 1080×1920 |
| `index.html` | браузерное превью обеих анимаций (крутится луп, есть скраб) |

## Что уже анимировано (можно править руками)

Луп 10 с. Таймлайн размечен маркерами: `Push-in 0` · `Hold 2.6` · `Push 2 4.2` · `Hold 2 6.0` · `Pull back 7.0` · `Loop 10`.

| Слой | Каналы | Что делает |
| --- | --- | --- |
| `Camera` | Position + Scale | камера: наезд 0–2.6 → пауза → второй наезд 4.2–6.0 → пауза → медленный отъезд 7.0–10 |
| `Glow` | Opacity + Scale | зелёное свечение «дышит» в такт дыханию персонажа |
| `Character` | Scale | дыхание грудью: 2 вдоха за луп, пивот внизу по центру фигуры |
| `Glint-crown` | Position + Scale + Opacity | блик на короне (≈3.2 с), проходит слева-направо |
| `Glint-sword` | Position + Scale + Opacity | блик на мече: 16:9 — на золотом навершии (≈7.5 с), 9:16 — скользит по клинку (≈6.7 с) |
| `Badge`, `Title`, `Subtitle`, `Chip-*` | — | статичны, лежат в камере (двигаются вместе с ней) |

Всё, что двигается, лежит внутри `Camera` — поэтому камера тянет за собой и UI, и персонажа.

## Как править в Keyshape

1. Открыть `.keyshape` (это zip с `document.keyshapex`; Keyshape открывает как обычный проект).
2. Выбрать слой → в таймлайне справа каналы: Position (motion path), Scale, Opacity.
3. Ключи **абсолютные, в секундах**; `ks:playRangeOut` — в **миллисекундах** (10000 = 10 с).
4. Пивот вращения/масштаба = позиция группы: контент внутри слоя сдвинут на `-пивот`, поэтому
   `Scale` крутится вокруг позиции объекта. Меняете пивот — пересчитайте motion-ключи.
5. Motion path **начинается в позиции объекта**: первая точка `path` = `translate` группы.
   Иначе объект прыгнет на старте.
6. `timing-functions` всегда на 1 меньше числа ключей.
7. Луп бесшовный: первый и последний ключ каждого канала совпадают, `repeat-end="indefinite"`.

Экспорт из Keyshape: `ks:export` уже настроен — `format="svg"`, `animation="css"`, `loop-count="0"`
(бесконечный луп).

## Пересборка

```bash
python3 tools/fetch_pieces.py   # только если менялись макеты в Figma
python3 tools/build.py          # .keyshape + preview/animation-data.js
python3 tools/validate.py       # проверка формата
open index.html                 # превью в браузере
```

`tools/build.py` — единственный источник истины: и `.keyshape`, и браузерное превью
генерируются из одних и тех же спеков, поэтому тайминги в превью и в Keyshape совпадают 1:1.
Ручные правки, сделанные в Keyshape, сборка **не** переносит — если правите руками,
правьте и в `build.py`, либо не пересобирайте.

## Технические заметки

- **Свечение** в Figma — эллипс #67B279 с blur 1000. Keyshape не поддерживает `<filter>`,
  поэтому блюр заменён радиальным градиентом с профилем, подобранным по рендеру Figma:
  `alpha(d) = 0.48 · exp(−(d/725)^2.05)`, радиус 1900. Визуально неотличимо от блюра.
- **Куски** выгружены по отдельности: REST-экспорт Figma сплющивает группы. Позиции взяты из
  `get_metadata`; для текста Figma отдаёт **ink-bbox** (`absoluteRenderBounds`), а не bbox фрейма —
  `tools/fetch_pieces.py` сам выбирает нужный origin по размеру viewBox.
- **`fill="none"`** у корневого `<svg>` каждого куска перенесён на группы-обёртки: без него
  фигуры без явного `fill` (например, обводка чипов) заливаются чёрным.
- **Блики** — четырёхлучевая звезда + мягкий ореол, отдельные слои; правятся как обычные векторы.
- Файлы проверяются `tools/validate.py`: zip, XML, число `timing-functions` = ключей−1,
  возрастание `abs-key-times`, последний ключ = длина лупа, все `url(#…)` резолвятся,
  `path[0]` = `translate`, каналы замыкаются.
